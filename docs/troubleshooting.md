# 问题排查

先看“此刻”或“流转”里那条点歌停在哪一步，再按现象查。部署时的问题见[部署教程的常见问题](deployment.md#常见问题)。

## 说了没有记录

| 原因 | 怎么确认 | 处理 |
| --- | --- | --- |
| 音箱没接入 | “音箱”里是“不接入” | 改成观察或接管 |
| 不是点歌 | 在“怎么说”输入原话 | 换一种说法 |
| 小米账号失效 | “设置”里小米账号是红点 | 重新登录 |
| 刚启动 | 日志有“已启动” | 启动前说的话不会补记，再说一次 |
| 型号不支持 | “音箱”里显示暂不支持 | M01 等型号暂时不能接入 |

## 有记录，没接管

| 记录写着 | 意思 |
| --- | --- |
| 曲库和线上都没有 | 歌确实没找到，或只有会员版。有网易云会员可在“设置 → 线上音源”扫码登录 |
| 延迟到达 | 小米两分钟后才给出这句话，为避免突然出声不执行 |
| 没有设置地址 | 没填 `TRACKFERRY_URL` |

## 接管了，没出声

看“流转”的步骤列表：

| 停在 | 多半是 |
| --- | --- |
| 推送音频 | 音箱离线，或小米没接受指令 |
| 推送后没有“音箱取流” | 音箱连不到 `TRACKFERRY_URL`：地址、防火墙、网段 |
| 有取流，没有“确认在播” | 音箱不认这首歌的格式，或被别的程序抢走 |
| 失败：又被别的播放占用 | 小爱或 xiaomusic 在同时控制 |

## 放歌前先听到小爱回答一大段

“音箱 → 压住小爱的回答”换成“加强”，没有这一档或还不行就换“等小爱说完”。见[使用说明](usage.md#压住小爱的回答)。

## 放错歌

“此刻”里写着选它的依据。把想要的版本在飞牛音乐里收藏，同名时会优先；或说全“歌手的歌名”。

## 线上音源总是失败

“设置 → 线上音源”显示每家最近的成功次数和错误。连续失败会暂停一段时间再试，不影响曲库。某一家不想用就关掉。

## 检查更新失败

NAS 连不上 GitHub，或短时间问得太多。在“设置 → 关于 → 设置代理”填代理地址，保存时会测试。不影响点歌，可用 `TRACKFERRY_UPDATE_CHECK: "off"` 关掉。

## 在线更新没有成功

页面会写明原因。连不上 GitHub 时设置代理，或改用命令更新；新版本启动不了会自动退回，日志里有一条“更新”说明。见[更新与退回](deployment.md#更新与退回)。

## 看日志

```sh
docker compose logs -f --tail 100 trackferry
```

每行是 `时间  级别  主题　内容  键=值`。没有级别的是日常，“注意”值得看一眼，“错误”需要处理。日志里没有密码、登录凭据和音频地址。需要更细的内容，加 `TRACKFERRY_DEBUG: "1"` 后重启。

## 反馈问题时

附上版本号（设置 → 关于）、音箱型号、那条点歌停在哪一步，以及相关几行日志。发出前去掉家里的地址和说过的话；不要附 `data/` 里的任何文件。
